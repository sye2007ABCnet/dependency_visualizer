# Визуализатор графа зависимостей пакетов (вариант №19)
 
## Общее описание
 
CLI-инструмент для построения и визуализации графа зависимостей пакетов
Ubuntu (apt). Реализован на Python 3 без внешних зависимостей. Готовые
менеджеры пакетов и библиотеки для получения зависимостей не
используются. Работа выполняется поэтапно, каждый этап находится в
отдельной ветке и содержит весь код предыдущих этапов.
 
## Функции и настройки
 
| Опция | Описание | По умолчанию |
|---|---|---|
| `-p`, `--package` | имя анализируемого пакета (обязательно) | — |
| `-r`, `--repo` | URL репозитория или путь к файлу тестового репозитория (обязательно) | — |
| `-t`, `--test-mode` | режим работы с тестовым репозиторием | выключен |
| `--package-version` | версия пакета (обязательна вне тестового режима) | — |
| `-o`, `--output` | имя файла с изображением графа (`.svg`) | `graph.svg` |
| `-a`, `--ascii-tree` | вывод зависимостей в виде ASCII-дерева | выключен |
| `-d`, `--max-depth` | максимальная глубина анализа (целое, ≥ 1) | `5` |
 
Каждый параметр проверяется. При ошибках выводятся сразу все найденные
проблемы, программа завершается с кодом 2.
 
### Этап 1
 
При запуске все параметры выводятся в формате `ключ=значение`.
 
### Этап 2: сбор данных
 
Приложение скачивает индекс пакетов репозитория Ubuntu (файл `Packages`,
`Packages.gz` или `Packages.xz`), находит запись заданной версии пакета
и выводит его прямые зависимости (поля `Pre-Depends` и `Depends`).
Менеджеры пакетов и сторонние библиотеки не используются: загрузка
выполняется через `urllib`, разбор индекса и зависимостей реализован
вручную.
 
Опция `-r` принимает:
 
- корень архива (`http://archive.ubuntu.com/ubuntu`) — используется
  индекс `dists/jammy/main/binary-amd64/Packages.gz`;
- прямую ссылку на индекс, оканчивающуюся на `Packages`, `Packages.gz`
  или `Packages.xz`, — для других выпусков и разделов.
Альтернативы выводятся через `|`, зависимости из `Pre-Depends`
помечаются `[Pre-Depends]`. Коды завершения: 0 — успех, 1 — ошибка
получения данных (сеть, пакет или версия не найдены), 2 — ошибка
параметров. На этапе 3 вывод прямых зависимостей заменён выводом графа.
 
### Этап 3: основные операции
 
Приложение строит граф зависимостей пакета с учётом транзитивности:
собираются зависимости зависимостей до глубины, заданной опцией `-d`.
Обход выполняется в глубину (DFS) без рекурсии, на явном стеке, поэтому
глубина графа не ограничена лимитом рекурсии Python. Граф выводится в
виде списка «пакет -> его зависимости» в порядке обхода.
 
**Ограничение глубины.** Корневой пакет лежит на глубине 0. Вершины на
предельной глубине попадают в граф, но их зависимости не раскрываются.
При `-d 1` получаются корень и его прямые зависимости. Если вершину
сначала достигли по длинному пути, а затем по короткому, она
раскрывается заново: так каждая вершина получает все зависимости,
доступные ей на минимальной глубине.
 
**Циклические зависимости.** Цикл — это ребро в вершину, которая лежит
на текущем пути обхода. Построение графа завершается и при циклах, а
найденные циклы выводятся отдельным списком (`A -> B -> A`).
Циклы ищутся вторым обходом в глубину по уже построенному графу и
выводятся по одному на каждое обратное ребро, а не все простые циклы
(их перебор экспоненциален). Цикл, не уместившийся в глубину анализа,
не показывается.
 
**Формат вывода.**
 
| Запись | Значение |
|---|---|
| `A -> B, C` | пакет A зависит от B и C |
| `D (нет зависимостей)` | у пакета нет зависимостей |
| `C [достигнута максимальная глубина]` | зависимости есть, но не раскрыты из-за `-d` |
| `X [нет в репозитории]` | пакет не найден в индексе или тестовом файле |
 
После списка выводятся число пакетов в графе и список циклов (или
сообщение, что циклов нет).
 
#### Тестовый репозиторий
 
Опция `-t` включает чтение графа из текстового файла вместо URL. Пакеты
называются большими латинскими буквами. Формат — по строке на пакет:
 
```
# комментарий
A: B C
B: D
D:
```
 
- пустые строки и строки, начинающиеся с `#`, пропускаются;
- зависимости перечисляются через пробел, повторы убираются;
- пакет, который указан только как зависимость и не описан отдельной
  строкой, считается отсутствующим в репозитории;
- корневой пакет `-p` должен быть описан в файле, версия не нужна.
Ошибки файла (нет двоеточия, недопустимое имя, повторное описание
пакета, корня нет в файле) сообщаются с номером строки, код
завершения 1.
 
Готовые файлы лежат в каталоге `fixtures/`:
 
| Файл | Что проверяет |
|---|---|
| `simple.txt` | общая зависимость (ромб) |
| `chain.txt` | цепочка A → F для проверки глубины |
| `cycle.txt` | простой цикл A → B → C → A |
| `cycles.txt` | несколько циклов и самозависимость |
| `shortcut.txt` | вершина, достижимая по длинному и по короткому пути (`-d 3`) |
| `unknown.txt` | зависимость, не описанная в файле |
| `invalid/` | три файла с ошибками формата |
 
#### Работа с репозиторием Ubuntu
 
- Версию задаёт пользователь только для корневого пакета. Остальные
  пакеты берутся из индекса по имени, ограничения версий
  (`>= 2.34`) не проверяются: в индексе одного выпуска у пакета, как
  правило, одна версия.
- Учитываются поля `Pre-Depends` и `Depends`, повторы убираются.
- Из группы альтернатив (`a | b`) выбирается первая, которая есть в
  индексе (так поступает и apt). Если нет ни одной, берётся первая по
  списку.
- Виртуальные пакеты (`Provides`) не разрешаются: такой пакет
  помечается как отсутствующий в репозитории.
- Пакеты из других разделов (например, `universe`) в индексе `main` не
  найдутся: для них нужно передать ссылку на нужный индекс.
Коды завершения те же: 0 — успех, 1 — ошибка получения данных (сеть,
пакет или версия не найдены, некорректный тестовый файл), 2 — ошибка
параметров.
 
## Структура проекта
 
| Путь | Назначение |
|---|---|
| `src/main.py` | точка входа, выбор режима, вывод, коды завершения |
| `src/config.py` | разбор и проверка параметров командной строки |
| `src/apt_repo.py` | загрузка и разбор индекса пакетов Ubuntu |
| `src/dependencies.py` | разбор полей `Depends` и `Pre-Depends` |
| `src/sources.py` | источники зависимостей: индекс apt и тестовый файл |
| `src/graph.py` | построение графа обходом в глубину, поиск циклов, вывод |
| `tests/` | модульные тесты (`unittest`), локальный HTTP-сервер для тестов |
| `fixtures/` | индекс пакетов для тестов и файлы тестовых репозиториев |
| `scripts/` | скрипты ручной проверки: `valid/` и `invalid/` |
| `Makefile` | запуск тестов и программы |
 
## Сборка и запуск тестов
 
Сборка не требуется.
 
```bash
make test
make run ARGS="-p A -r fixtures/simple.txt -t"
```
 
Без `make`:
 
```bash
PYTHONPATH=src python3 -m unittest discover -s tests -v
python3 src/main.py -p A -r fixtures/simple.txt -t
```
 
## Скрипты ручной проверки
 
Запускаются из любого каталога, показывают команду и код завершения.
Скрипты в каталоге `valid/` содержат корректные запуски, в `invalid/` —
ошибочные.
 
| Скрипт | Что показывает |
|---|---|
| `valid/stage1.sh` | этап 1: корректные запуски |
| `invalid/stage1.sh` | этап 1: ошибки каждого параметра (код 2) |
| `valid/stage2.sh` | этап 2: зависимости из настоящего репозитория |
| `valid/stage2_apt_compare.sh` | этап 2: сверка со штатным `apt-cache` |
| `invalid/stage2.sh` | этап 2: ошибки получения данных (код 1) |
| `valid/stage3.sh` | этап 3: тестовые репозитории, глубина, циклы |
| `valid/stage3_real.sh` | этап 3: граф для curl и git из репозитория Ubuntu |
| `invalid/stage3.sh` | этап 3: ошибки тестового файла (код 1) |
 
```bash
bash scripts/valid/stage3.sh
bash scripts/invalid/stage3.sh
bash scripts/valid/stage3_real.sh
```
 
Скрипты выполняют текущий код ветки, поэтому на ветке этапа 3 скрипты
этапов 1 и 2 показывают уже вывод этапа 3. Скрипты с настоящим
репозиторием требуют доступа в интернет.
 
## Примеры использования
 
### Этап 1
 
```
$ python3 src/main.py -p curl -r http://archive.ubuntu.com/ubuntu \
      --package-version 7.81.0-1ubuntu1 -a -d 3
package=curl
repo=http://archive.ubuntu.com/ubuntu
test_mode=False
version=7.81.0-1ubuntu1
output=graph.svg
ascii_tree=True
max_depth=3
 
$ python3 src/main.py -p Bad_Name -r archive -o g.png -d 0
ошибка: имя пакета 'Bad_Name' недопустимо: допускаются строчные латинские буквы, цифры и символы + - . (не короче 2 символов)
ошибка: 'archive' не является URL-адресом (ожидается http:// или https://)
ошибка: версия пакета обязательна вне тестового режима
ошибка: файл изображения 'g.png' должен иметь расширение .svg
ошибка: максимальная глубина должна быть не меньше 1
```

### Этап 3
 
Тестовый репозиторий: общая зависимость и ограничение глубины.
 
```

  C -> D
Пакетов в графе: 4

$ python3 src/main.py -p A -r fixtures/chain.txt -t -d 2

  A -> B
  B -> C
  C [достигнута максимальная глубина]
Пакетов в графе: 3
Циклических зависимостей не найдено.
```
